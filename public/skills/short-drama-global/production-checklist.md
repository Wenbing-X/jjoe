# AI 短剧制作与交付检查清单

这份清单把故事、镜头、画面、声音与成片连接成可审阅的制作链路。它是方法文档，不表示下列开源工具已全部接入本站或已有海外发行成果。先读[短剧出海 Skill](./SKILL.md)，需要表单时使用[工作模板](./templates.md)。

## 工具与交接

1. **脚本与镜头**：把已确认脚本拆成逐镜头表，记录人物、地点、动作、台词、时长和预期情绪。以镜头 ID 作为全部素材的共同索引。
2. **视觉锚点**：先选定角色外观、服装、场景和画风参考。每次生成时记录工具、工作流版本、提示词、种子或其他可复现参数；对定妆照和关键帧人工挑选。
3. **镜头视频**：由通过审核的关键帧制作短镜头。若使用 ComfyUI、即梦或其他工具，先核对模型和素材的使用许可与具体任务适配性；不同工具可以产生同一镜头 ID 的候选版。
4. **声音与合成**：按镜头表组织配音、音效、音乐、字幕和剪辑；需保留授权与来源。可按项目选择剪映、FFmpeg 或其他适合的工具，不预设必须使用某一套自动化脚本。
5. **导出与发布**：以目标渠道当时的官方要求核对技术规格，再人工通看最终文件。将母版、渠道版、字幕、封面、发布文案和权利记录一起交付。

GitHub 参考：[AI Director Skills](https://github.com/hzw1199/AI-Director-Skills) 展示故事诊断、镜头表、角色锚点与本地生成的衔接；[Story Claw](https://github.com/ZC89757/story-claw) 展示长故事拆解为短剧集的流程；[ComfyUI Workflows](https://github.com/w993322800/comfyui_workflows) 展示定妆、分镜、视频、TTS 和合成的模块分工。本文只借鉴流程设计，未复制其代码或工作流文件。

## 建议的项目目录

```text
项目代号/
  00_brief/           市场 Brief、来源与审批记录
  01_script/          梗概、分集脚本、镜头表
  02_locale/          术语表、翻译、字幕与人工复核
  03_assets/          characters/、frames/、shots/、audio/
  04_edit/            剪辑工程、首剪与修改意见
  05_delivery/        母版、渠道版、封面与授权清单
  06_review/          发布记录、数据与复盘
```

统一命名：`项目_集号_镜头号_语种_v版本`，例如 `P01_E01_S003_en-US_v02.mp4`。保留已审核版本，修改原因记入项目日志。任何工具生成的临时文件不要直接覆盖交付母版。

## 四个质量关口

| 关口 | 通过前要核对 | 未通过时 |
| --- | --- | --- |
| 脚本确认 | 冲突和人物动机清楚；开头钩子成立；镜头量与资源匹配 | 回到梗概或分集脚本，不启动批量生成 |
| 视觉确认 | 角色身份、服装、场景与画风有统一参考；关键帧支持动作起点 | 修改角色锚点或单镜头关键帧 |
| 首剪确认 | 镜头叙事连续；配音与字幕对应；节奏可看懂 | 按时间码记录问题，只重做受影响的镜头 |
| 导出确认 | 技术规格、字幕、声音、素材权利、文件播放和发布文案均通过 | 返回相应制作环节，保留旧版并复核新版 |

## 最终交付前逐项检查

- 从头到尾播放**实际导出文件**，核对黑帧、跳帧、片尾截断和声音缺失。
- 对照脚本检查镜头顺序、人物连续性、字幕拼写与时间轴；重点检查手机端安全区域与可读性。
- 核对目标渠道当前要求的画幅、分辨率、帧率、编码、时长和封面；记录要求来源与检查日期。
- 核对音乐、素材、字体、真人形象与生成内容的使用权，记录来源和授权范围。
- 用版本号区分母版和各语种 / 渠道版，附变更记录、字幕文件和发布文案。
- 若要展示成果，注明是试制样片、正式发布作品，还是第三方开源项目；不要把后者写成个人案例。
